Date: 2026-11-01. Scope: check the application against the project checklist (SEO/GEO/AEO, interface conventions, security, privacy, error pages, tests, clean-up) and fix what was missing. Most items had been delivered in phases 1 to 9; this phase verified each one against the code and the running site, then closed the gaps.

| Area | Before | After |
| --- | --- | --- |
| `autocomplete="off"` | Missing on 60 `<form>` tags and 29 inputs/selects (44 views) | On every form and text-like control |

## Tests added

`tests/Feature/Security/UiConventionsTest.php` (11 tests) reads the Blade views and front-end sources, so a new screen that breaks a rule fails the build:

- every form and text-like control has `autocomplete="off"` (aware of quotes and `{{ }}`);
- no native `alert()`/`confirm()`/`onsubmit`, no jQuery;
- no `gray-*` in views or `app.css`;
- unescaped output only in the JSON-LD component, with the hex-escape flags;
- the navigation says "Painel" and the landing has no "Dashboard";
- the search boxes carry `data-debounce-submit`, and `forms.js` keeps the in-flight guard and the `pageshow` release;
- the write limit blocks the 4th write of a user (429), never counts GET, and does not affect other users;
- breadcrumbs come from the component and emit `BreadcrumbList`;
- external tabs use `rel="noopener noreferrer"`;
- the production defaults of the session cookie.

Existing coverage that already exercised the rest: `CrawlerTest` (every route and link), `UserJourneyTest`, `HardeningTest`, `QueryBudgetTest`, `ErrorPagesTest`, `SeoTest`, and the k6 scripts in `tests/load` for load and stress runs.

Result: 1074 passed, 15 skipped (5184 assertions); `composer quality` exits 0.

## Left as it is, on purpose

- **Unused kit components** `ui/card`, `ui/icon-box`, `ui/stat-card` and `ui/textarea` have no caller today. They are part of the documented design system (the style guide lists them), so they stay for new screens instead of being deleted and rewritten later.
- **CSP keeps `'unsafe-inline'` and `'unsafe-eval'`.** Alpine's standard build evaluates `x-*` expressions with `Function()`, and several views have inline scripts. Removing them means moving to Alpine's CSP build and nonces, a larger front-end change with its own risk.
- **Honeypot on the other forms**: see the table above.
- **No visual redesign.** The interface already follows the "Confiança serena" design system (evergreen + amber, Inter and Fraunces, light and dark). A redesign needs a direction from the product owner; changing it page by page without one would only add inconsistency.
- **Load and stress tests (k6)** are not run here (k6 is not installed). Run them against staging as described in `tests/load/README.md`. The local PHP server answers `/` in about 390 ms and `/login` in about 310 ms with a single worker, which says little about production.
- **Apache rules** in `public/.htaccess` are not exercised by `php artisan serve`; check `X-Powered-By`, gzip and `/.env` on the real server after the deploy.

## Server notes

The deploy is FTP only, so after uploading: `php artisan optimize:clear`, rebuild `public/build/` (the CSS changed: `gray-*` became `surface-*`), and remove `vendor/laravel/breeze` (or upload the new `vendor/`). In production keep `APP_DEBUG=false`; if `SESSION_SECURE_COOKIE=null` was copied from the old `.env.example`, delete the line, because an explicit `null` overrides the new default.
