## Design decisions (made here, not left to the coder)

- **Order**: Part B fixes first (small, independent), then Laravel Data (TransactionDTO gains receipt fields in step 4 and reports get a Data filter object in step 5), then Activitylog, Media Library, Excel + report service + cache, Queue + docs + final verification.
- **Polymorphic UUIDs**: users and all domain models use UUID keys, so the published `activity_log` migration must use `nullableUuidMorphs('subject')` / `nullableUuidMorphs('causer')` and the `media` migration `uuidMorphs('model')`. Package tables keep their bigint `id` and have no SoftDeletes, same as the Spatie permission tables (documented exception, as in docs/security/phase-1-acl-audit.md §"Spatie tables keep bigint ids").
- **Activity causer**: a new trait `App\Traits\LogsOwnedActivity` wraps the package `LogsActivity` with an explicit per-model attribute allowlist, `logOnlyDirty()`, `dontLogEmptyChanges()`. Its `beforeActivityLogged()` sets causer = the model owner (`user_id`) and property `via=system` when no user is authenticated (scheduler, Stripe webhook, queue), so every model activity has a causer. Failed logins are the one exception: the actor is unknown, so causer is null and subject is the targeted user (if any). Auth/security events go through a small `SecurityActivityLogger` service (interface + implementation).
- **Activity page isolation**: `ActivityRepository::paginateForUser($userId)` returns rows where (causer = this user) OR (subject = this User AND causer IS NULL). The route has no id parameter, so another user's log is not addressable.
- **Never logged**: `User` model attributes, `AiCredential` (API keys), passwords, remember tokens, Stripe ids, `wallets.company_document`, `wallets.balance` (balance moves are already covered by the transaction rows), transaction `notes`, failed-login credentials. Auth events store only the IP address.
- **Role changes**: set `config/permission.php` `events_enabled => true` and listen to `Spatie\Permission\Events\RoleAttachedEvent` / `RoleDetachedEvent`. Plan changes come from the logged `Subscription` model (`plan`, `status`, `cancel_at_period_end`, `current_period_end`, `canceled_at`).
- **Receipts**: a `ReceiptServiceInterface`/`ReceiptService` owns attach/remove/response. The upload file and a `remove_receipt` flag travel in `TransactionDTO` as non-persisted instructions (like `installments`/`reason` today), so `TransactionService` attaches inside its DB transaction and the history diff still records "Comprovante". Receipt removal is an edit-form checkbox (no new route). Removal clears the media collection and sets `receipt_path` to null (the legacy file itself is never deleted). Path generator: `receipts/{user_id}/media/{media uuid}/`, so the existing "intruder stores nothing under receipts/{intruder}" test keeps working.
- **Media mime check**: `acceptsMimeTypes(['image/jpeg','image/png','application/pdf'])` + `max_file_size` 5 MB. Media Library sniffs content (finfo), so tests must upload real minimal content (`UploadedFile::fake()->createWithContent('nota.pdf', "%PDF-1.4\n%...")`). A `FileUnacceptableForCollection` is converted to a `ValidationException` on `receipt` with the existing pt-BR message, which also rolls back the DB transaction.
- **Exports**: `App\Exports\TransactionsExport` (FromCollection, WithHeadings, WithMapping, WithCustomCsvSettings) is the single source of columns for CSV, XLSX and the e-mail attachment. Downloads keep `response()->streamDownload()` wrapping `Excel::raw(...)`, so existing tests that call `streamedContent()` keep working. Format is a `format=csv|xlsx` query parameter on the existing `reports.export` route (same middleware, same plan check). XLSX uses the same string columns as CSV (one mapping, identical columns).
- **Report service + cache**: `ReportController::buildReport()` moves to `ReportServiceInterface`/`ReportService::build(User, ReportFilterData)`. Validation moves to a new `ReportRequest` Form Request (same rules + `format`). `ReportFilterData` is a new spatie/laravel-data class. Only the aggregate "summary" (no Eloquent models) is cached; the transaction list is always read live.
- **Cache keys**: `UserCacheInterface`/`UserCache` with version-key invalidation (the `database` store does not support tags). Key = `finestro:user:{userId}:v{version}:{name}:{md5(json(sorted params))}`; flush = write a new random version to `finestro:user:{userId}:version`. TTL from `config('cache.user_ttl')` (env `CACHE_USER_TTL`, default 300 s). With no authenticated user the cache is bypassed. Invalidation: trait `App\Traits\FlushesUserCache` on Transaction, Wallet, Goal, Budget flushes the owner on created/updated/deleted/restored/forceDeleted. `Model::increment()` fires `updated`, so wallet balance changes invalidate too. Cached: `TransactionService::getSummary()` (dashboard and transactions index) and the report summary.
- **Queue**: both mailables implement `ShouldQueue` with `$tries = 3`, `$backoff = [60, 300]`, and are sent with `->queue()`. `FinancialReportMail` gets the scalar report summary (no Eloquent collections in the payload) plus the CSV string. Breeze notifications are queued via `App\Notifications\QueuedVerifyEmail` / `QueuedResetPassword` subclasses, used by `User::sendEmailVerificationNotification()` / `sendPasswordResetNotification()`. The 3 `PasswordResetTest` assertions and 2 `Mail::assertSent(FinancialReportMail…)` assertions are updated to the queued classes/`assertQueued` (same intent). The `jobs`/`failed_jobs` tables already exist (`0001_01_01_000002_create_jobs_table.php`, migrated), so no queue migration is needed. Shared-hosting fallback: optional scheduler entry `queue:work --stop-when-empty --max-time=50` behind env `QUEUE_RUN_VIA_SCHEDULER` (default false), so a single cron line is enough.
- **Part B-1**: `StripeGateway::cancelImmediately()` maps Stripe `InvalidRequestException` with code `resource_missing` (or HTTP 404) to a new `App\Exceptions\StripeResourceMissingException`. `AccountDeletionService` catches that one exception, marks the local subscription canceled through a new `SubscriptionService::markCanceledLocally()`, and continues the deletion. Every other `\Throwable` still blocks deletion.
