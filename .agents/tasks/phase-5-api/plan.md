## Design decisions (made here, do not re-decide)

1. **Packages** (verified on Packagist, all support Laravel 13): `laravel/sanctum:^4.3` (4.3.3), `laravel/scout:^11.9` (11.9.0), `darkaonline/l5-swagger:^11.2` (11.2.2, pulls `zircote/swagger-php` ^6.12||^7). Use PHP 8 attributes (`OpenApi\Attributes as OA`), never docblock annotations.
2. **Sanctum token-only.** `config/sanctum.php` → `'guard' => []` (a browser session can never call the API), no `statefulApi()`. `'expiration' => env('SANCTUM_TOKEN_EXPIRATION', 129600)` minutes (90 days); tokens are also created with `expiresAt = now()->addMinutes(expiration)` so the list can show it. Schedule `sanctum:prune-expired --hours=24` daily in `routes/console.php`. `personal_access_tokens` keeps Sanctum's bigint `id` (the plain token format is `{id}|{secret}`) and no SoftDeletes (revocation = delete); `tokenable` becomes `uuidMorphs`. Document this as a framework-table exception, like the Spatie tables in Phase 1.
3. **Token abilities** = new enum `App\Enums\ApiTokenAbility` (string-backed): `account:read`, `wallets:read`, `wallets:write`, `transactions:read`, `transactions:write`, `goals:read`, `goals:write`, `budgets:read`, `budgets:write`, `categories:read`, `categories:write`, `reports:read`. Methods: `label(): string` (pt-BR), `static values(): list<string>`, `static options(): array<string,string>` (same style as `App\Enums\PaymentMethod::options()`). Routes enforce them with Sanctum's `abilities:` middleware (`Laravel\Sanctum\Http\Middleware\CheckAbilities`).
4. **Plan gating**: no API feature exists today (`User::hasFeature` has `default => true`, so an explicit arm is mandatory). Add `'api_access'` to `User::getPlanLimitsAttribute()` (professional `true`, free `false`, update the `@return array{...}` shape) and a `'api_access' => $limits['api_access']` arm in `hasFeature()`. Add "Acesso à API REST com tokens pessoais" to `config/stripe.php` professional `features` and "Acesso à API REST" to free `limitations`. Middleware `App\Http\Middleware\EnsureApiAccess` (alias `api.plan`) returns 403 `plan_upgrade_required` for users without the feature (also covers downgraded users holding old tokens).
5. **API routing**: `bootstrap/app.php` `->withRouting(api: __DIR__.'/../routes/api.php', ...)` (default prefix `api`). `routes/api.php`: `Route::prefix('v1')->name('api.v1.')->middleware(['auth:sanctum', 'verified', 'throttle:api', 'api.plan'])`. Throttle goes after `auth:sanctum` so the limiter key is the user. `$middleware->api(prepend: [ForceJsonResponse::class])` sets `Accept: application/json`. Guests are never redirected for `api/*` (`$middleware->redirectGuestsTo(fn (Request $r) => $r->is('api/*') ? null : route('login'))`).
6. **Rate limiter** `RateLimiter::for('api', ...)` in `AppServiceProvider::boot()`: `Limit::perMinute((int) config('api.rate_limit_per_minute'))->by('api:'.($request->user()?->getAuthIdentifier() ?? $request->ip()))`. Keyed per user (not per token) so creating more tokens never multiplies the quota. New `config/api.php`: `rate_limit_per_minute => (int) env('API_RATE_LIMIT_PER_MINUTE', 60)`, `per_page_max => 100`, `docs_public_in_local => true`.
7. **Error envelope** for every `api/*` response: `{"message": "<pt-BR>", "code": "<snake_case>", "errors": {...}}` (`errors` only on 422). One class `App\Exceptions\ApiExceptionRenderer` with `render(Throwable $e, Request $request): ?JsonResponse`, wired in `bootstrap/app.php` `->withExceptions(fn (Exceptions $e) => $e->render(fn (Throwable $t, Request $r) => $r->is('api/*') ? app(ApiExceptionRenderer::class)->render($t, $r) : null))`. Mapping:
   - `AuthenticationException` → 401 `unauthenticated` "Não autenticado. Envie um token válido no cabeçalho Authorization: Bearer."
   - `Laravel\Sanctum\Exceptions\MissingAbilityException` → 403 `missing_ability` "Este token não tem a permissão necessária para esta ação." (+ `abilities` list of the missing ones from `$e->abilities()`).
   - `App\Exceptions\PlanLimitException` (new; `__construct(string $message, string $errorCode = 'plan_limit_reached')`) → 403 with its message/code. `EnsureApiAccess` throws it with code `plan_upgrade_required`.
   - `AuthorizationException`: if `$e->hasStatus() && $e->status() === 404` (policies' `denyAsNotFound()`) → 404 `not_found`; else 403 `forbidden` with the policy message (already pt-BR) or "Você não tem permissão para realizar esta ação.". `Spatie\Permission\Exceptions\UnauthorizedException` → 403 `forbidden`.
   - `ModelNotFoundException`, `NotFoundHttpException` → 404 `not_found` "Recurso não encontrado." (never echo the model class or id).
   - `ValidationException` → 422 `validation_failed` "Os dados enviados são inválidos." + `errors` (`$e->errors()`).
   - `ThrottleRequestsException` → 429 `too_many_requests` "Muitas requisições. Aguarde e tente novamente." keeping `$e->getHeaders()` (Retry-After, X-RateLimit-*).
   - Other `HttpExceptionInterface` → its status, code `http_error`, generic pt-BR message (e.g. 405 "Método não permitido.", 403 from `verified` "Confirme seu e-mail para usar a API.").
   - Anything else: return `null` when `app()->isLocal() && config('app.debug')` (default debug output); otherwise 500 `server_error` "Erro interno. Tente novamente mais tarde." with no trace. Reporting is unaffected.
8. **Controllers** in `app/Http/Controllers/Api/V1/` reuse the existing services, policies, Form Requests and plan checks. Same order as web: scoped lookup → `?? abort(404)` → `$this->authorize(...)` → service. Plan limits throw `PlanLimitException` with the same pt-BR texts as the web controllers. Status codes: store 201 + resource, update/pay/unpay 200 + resource, destroy 204.
9. **Pagination**: list endpoints for wallets, transactions, goals, categories return Laravel's resource-collection paginator envelope (`data`, `links`, `meta`), `per_page` 1..100 (default 20). Add additive `paginate(array $filters, int $perPage)` methods to Wallet/Goal/Category repositories + services (+ interfaces). Budgets are per month and bounded by the user's categories, so `GET budgets` returns `data` + `meta {year, month, overview}` without pagination (documented).
10. **Resources** `app/Http/Resources/V1/*Resource.php` use explicit allowlists (never `parent::toArray`). Never output `user_id`, `deleted_at`, `receipt_path`, media rows/paths, Stripe ids, `company_document` of a wallet the caller does not own.
11. **Scout** (`database` driver). `Transaction` uses `Laravel\Scout\Searchable`; `toSearchableArray()` returns keys `description`, `notes`, `categories.name`, `wallets.name`; `newScoutQuery()` left-joins `categories`/`wallets` on the transaction's own FKs and selects `transactions.*`. The database engine qualifies dotted column names as-is (`Model::qualifyColumn` returns names containing a dot unchanged), so the join columns are searched. The user scope still applies because `newScoutQuery()` starts from `$this->newQuery()` (global scope `user` → `transactions.user_id = Auth::id()`), and SoftDeletes stays qualified. Scout does not escape LIKE wildcards, so the repository escapes `\`, `%`, `_` before calling `Transaction::search()`. `TransactionRepository::filteredQuery()` replaces `->search(...)` with `whereIn('transactions.id', Transaction::search($escaped)->query(fn ($q) => $q->select('transactions.id'))->keys())`, so the list, the cached summary and the overdue count keep using the same filtered query. `scopeSearch` is removed (it would shadow/confuse `Searchable::search()`). Only Transaction is searchable (Goal/Category stay as-is; documented).
12. **Swagger UI** at `/api/documentation` (l5-swagger default). Docs routes get middleware `['web', App\Http\Middleware\EnsureApiDocsAccess::class]`: allowed when `app()->isLocal()`, or when the session user has role `admin`; guests elsewhere → 404, authenticated non-admins → 403. `L5_SWAGGER_GENERATE_ALWAYS=false`. Generated JSON lives in `storage/api-docs/` (git-ignored via its own `.gitignore`); deploy runs `php artisan l5-swagger:generate`.
13. **CORS**: publish `config/cors.php` (`php artisan config:publish cors`): `paths => ['api/*']`, `allowed_origins => array_filter(explode(',', env('CORS_ALLOWED_ORIGINS', env('APP_URL', ''))))`, `allowed_methods => ['GET','POST','PUT','PATCH','DELETE','OPTIONS']`, `allowed_headers => ['Authorization','Content-Type','Accept','X-Requested-With']`, `supports_credentials => false`, `max_age => 600`.
14. **Token UI** under Settings: `GET/POST /configuracoes/tokens` and `DELETE /configuracoes/tokens/{tokenId}` (names `settings.tokens.index|store|destroy`), `ApiTokenController` → `ApiTokenServiceInterface` → `ApiTokenRepositoryInterface` (queries only through `$user->tokens()`), DTO `App\DTOs\ApiTokenData` (Laravel Data: `name`, `abilities`). The plain token is flashed once (`session()->flash('plain_token', ...)`, PRG so a reload never re-creates a token) and never logged. Activity: `SecurityActivityLogger::log('api_token_created'|'api_token_revoked', $user, ['token_name' => ..., 'abilities' => [...]])`.
15. **Part C-1** Stripe: `StripeGateway::isModeMismatch(Throwable)` (message contains `a similar object exists in` — Stripe's text for live/test mode mismatch); `isResourceMissing()` returns false when it matches, so the generic failure branch blocks the deletion. `AccountDeletionService` logs the resource_missing shortcut with `Log::error`. New `App\Services\StripeConfigCheck` (+ `StripeConfigCheckInterface`): `isTestKeyInProduction(): bool` (`app()->isProduction()` and secret starts with `sk_test_`) and `reportIfMisconfigured(): void` (`Log::critical(...)` once per day via `Cache::add('finestro:stripe:test-key-warning', true, now()->addDay())`, never the key). Called from `AppServiceProvider::boot()` when production. The "admin side" is the authenticated layout: an `x-ui.alert variant="danger"` partial shown to role `admin` only (Filament admin is a later phase).
16. **Part C-2** receipts follow the DB transaction: `ReceiptService::remove()` deletes the media rows with `Media::withoutEvents()` (skips Spatie's `MediaObserver::deleted` file removal) and defers `app(\Spatie\MediaLibrary\MediaCollections\Filesystem::class)->removeAllFiles($media)` with `DB::afterCommit()`. `attach()` first calls `remove()` (so Spatie's singleFile auto-clear never deletes the old file mid-transaction) and returns the new `Media`. `ReceiptService::discard(Media ...$media)` deletes written files. `TransactionService::createTransaction()`/`updateTransaction()` wrap `DB::transaction()` in `try/catch (Throwable)`: on failure they call `discard()` on media written in this call and rethrow. RefreshDatabase's wrapper transaction is ignored by Laravel's transaction manager, so `afterCommit` callbacks run in tests.
17. **Part C-3** activity names: `WalletRepositoryInterface::namesForUser(string $userId, array $ids): array<string, array{name: string, deleted: bool}>` and the same on `CategoryRepositoryInterface` (`withoutGlobalScope('user')->withTrashed()->where('user_id', $userId)->whereIn('id', $ids)`). `AccountActivityService::paginateForUser()` collects `wallet_id`/`category_id` values from the page, resolves them in 2 queries, and prints `Nome`, `Nome (excluída)` (soft-deleted) or `(excluída)` (not found for this user, which also hides foreign ids).
