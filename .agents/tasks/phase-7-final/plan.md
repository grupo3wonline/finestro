## Design decisions (made here, binding)

- **Legacy pages**: `/sobre`, `/servicos`, `/ferramentas` become `Route::permanentRedirect('/sobre', '/#sobre')->name('about')` (same for services/tools), so `route('about')` keeps working; delete `PageController::about/services/tools`. `/contato` becomes a real page (`PageController::contact` returns `pages.contact`).
- **Contact**: one partial `resources/views/components/contact/channels.blade.php` (WhatsApp + e-mail + Grupo 3W Online card + CTA) included by `landing/home.blade.php` `#contato` and `pages/contact.blade.php`. Values come from new `config/marketing.php` (`contact.whatsapp_display`, `contact.whatsapp_number` = `5541996924829`, `contact.whatsapp_text`, `contact.email`).
- **3W CTA**: Blade component `resources/views/components/cta/agency.blade.php` (`<x-cta.agency variant="landing|page|auth|app|error" />`), root element carries `data-cta="3wonline"`, link `https://www.3wonline.com.br/?utm_source=finestro&utm_medium=cta&utm_campaign={variant}`, `target="_blank" rel="noopener"`. Copy variants are a `match` inside the component. Honest triggers only: `config('marketing.cta.monthly_slots')` ("Atendemos no máximo N novos projetos por mês"), "Agenda aberta em {mês}" (from `now()->translatedFormat('F')`), diagnóstico gratuito, resposta em até 24h úteis. No countdowns/fake numbers. The component is rendered by the layouts (landing, guest, app) just above the footer so every page has it; `app` variant is one compact strip. Remove the 3W block from `components/cta/main.blade.php` (keeps the Finestro Pro block) to avoid a duplicate.
- **Header on all pages**: extract the landing `<nav>` into `components/layout/public-header.blade.php` (wrapped in `<header role="banner" x-data="{ mobileMenu: false }">`); `layouts/landing` and `layouts/guest` include it. App pages keep `components/layout/header.blade.php` (already `role="banner"`). Guest layout uses the shared `components/layout/footer.blade.php`.
- **Footer text**: one plain text node `Sistema desenvolvido pelo desenvolvedor HOTWYL | WILLFROMBRASIL` (no inner tags, so tests can `assertSee` it). Social icons with `href="#"` are rendered only when `config('marketing.social.*')` URLs are set (default empty).
- **Truthful copy**: remove fabricated numbers from the landing (`+500 Usuários ativos`, `+10.000`, `+1.200`, `99,9%`, `+500 pessoas já usam`), `cta/main` ("Junte-se a centenas de pessoas"), and the fake `aggregateRating` JSON-LD. No testimonials (none are real).
- **Landing content**: static content in `App\Support\Landing\LandingContent` (`faq()`, `steps()`, `tips()` returning pt-BR arrays) used by both the visible markup and JSON-LD (FAQPage, HowTo). No DB access on `/` (`tests/Feature/ExampleTest.php` has no RefreshDatabase).
- **Login**: fields `username`, `email`, `password`. `LoginRequest::credentials()` returns `['username' => …, 'email' => lowercased …, 'password' => …]`; Laravel's `EloquentUserProvider::retrieveByCredentials` adds a `where` per non-password key, so both must belong to the same user. Generic error stays on the `login` error key (`trans('auth.failed')`), so `EnsureAccountIsActive` and suspension logic stay unchanged. Throttle key `lower(username)|lower(email)|ip`, 5 attempts.
- **Policy versioning**: `config/legal.php` `policy_version` (env `LEGAL_POLICY_VERSION`, default `2026-07`) + `policy_updated_at`. New nullable `users.terms_version` (additive migration). `EnsureTermsAccepted` redirects when `terms_accepted_at` is null OR `terms_version !== config('legal.policy_version')`. Terms acceptance moves from the route closure to `App\Http\Controllers\TermsAcceptanceController` + `App\Services\LegalConsentService` (interface `LegalConsentServiceInterface`) which sets both columns and logs `terms_accepted` (`{version}`). Registration sets `terms_version`. UserFactory sets `terms_version`.
- **Cookie consent**: first-party cookie `finestro_consent` (JSON `{"v":version,"a":0|1,"m":0|1,"t":unix}`, 365 days, SameSite=Lax, not HttpOnly, excluded from encryption in `bootstrap/app.php` via `$middleware->encryptCookies(except: ['finestro_consent'])`). Single write path `POST /consentimento` (`consent.store`, `ConsentController@store`, `StoreConsentRequest`, throttle 30/min, guests and users) → `ConsentService::record()` queues the cookie and, for logged-in users, inserts a `cookie_consents` row and logs `consent_updated`. GPC: `Sec-GPC: 1` header or `navigator.globalPrivacyControl` forces `marketing=false` (stored `gpc=true`). Version mismatch = no consent.
- **Analytics gating**: move the loader out of Blade into `resources/js/consent.js` (Vite bundle, imported by `app.js`). `components/layout/analytics.blade.php` only emits `<script type="application/json" id="finestro-consent-config">@json([...ids, version, endpoint, gpc])</script>`; no vendor URLs in HTML before consent. GTM/GA4 get Consent Mode v2 defaults (all `denied`) pushed before load, then `consent update` per category. Meta Pixel only with marketing consent. `gtm-noscript` renders only when the server-side cookie grants analytics.
- **CSP**: narrow additions only in `SecurityHeaders`: `connect-src`/`script-src` add `https://*.google-analytics.com https://*.analytics.google.com https://www.facebook.com`; add `X-Robots-Tag: noindex, nofollow` for paths `admin*` and `api/*` (covers `/api/documentation`). Documented in docs/seo and docs/compliance.
- **DSR export**: table `data_exports`, model `DataExport`, enum `DataExportStatus`, job `App\Jobs\GeneratePersonalDataExport`, `DataExportService` + `PersonalDataRepository` (explicit `withoutGlobalScopes()->where('user_id', …)` because queued jobs have no auth user), zip with `data.json` + one CSV per section on `local` disk `exports/{user_id}/{export_id}.zip`, download via temporary signed route + ownership (BelongsToUser scope ⇒ 404 for other users), TTL `config('privacy.export_ttl_hours', 24)`, command `privacy:purge-exports` scheduled daily.
- **Account deletion copy is truthful**: `AccountDeletionService` soft-deletes; UI and policy say access ends immediately, subscription is cancelled, data is deactivated and permanent erasure can be requested via the DPO e-mail. Automated hard purge is listed as deferred.
- **SEO**: `config/seo.php` `indexable_routes` = `home, contact, faq, privacy, terms, cookies`; `seo-head` emits `index, follow` only for those, else `noindex, nofollow` (auth, app, error pages). JSON-LD built from PHP arrays by `App\Services\StructuredDataService` (interface) and printed by `<x-seo.json-ld :data="…" />` with `json_encode(JSON_UNESCAPED_UNICODE|JSON_UNESCAPED_SLASHES|JSON_HEX_TAG|JSON_HEX_AMP|JSON_HEX_APOS|JSON_HEX_QUOT|JSON_THROW_ON_ERROR)`. WebSite SearchAction targets the public help search `/ajuda?q={search_term_string}` (a real public search). `llms.txt` is a route (`PageController@llms`) so prices come from `PlanPricing`; do NOT create a static `public/llms.txt`.
- **Images**: generate `public/og-image.png` (1200×630), `public/apple-touch-icon.png` (180), `public/icon-192.png`, `public/icon-512.png` once with a throwaway GD script kept in `.agents/tasks/phase-7-final/tools/` (not in app code) using a Windows TTF font; reference them from `seo-head` and `manifest.json` (theme_color `#039855`).
- **UTM**: `App\Support\Utm::fromRequest(Request): array` (whitelist `utm_source|utm_medium|utm_campaign|utm_term|utm_content`, `[A-Za-z0-9._-]{1,100}`), used as `route('register', $utm)` on landing and contact sign-up CTAs.
- **Crawler scope**: skips route names starting with `filament.`, `livewire.`, `l5-swagger.`, `sanctum.`, `storage.`, `ignition.`, `api.`, signed routes, and non-GET; admin panel is covered by existing `tests/Feature/Admin/*`. Pages exempt from header/footer/CTA assertions: `reports.pdf`, `reports.print`, `reports.export`, `transactions.receipt`, `settings.privacy.download`, `robots`, `sitemap`, `llms` (non-HTML or print-only) — documented.
