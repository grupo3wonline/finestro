## Design decisions (made here, with rationale)

1. **Single price source = `config/stripe.php` + `App\Services\PlanPricing`.** Config holds `plans.professional.price = (float) env('STRIPE_PROFESSIONAL_PRICE', 29.90)` and a new top-level `promo` block. A small service `PlanPricing` (interface `App\Interfaces\Services\PlanPricingInterface`) is the only code that reads those keys; views use `@inject('pricing', \App\Interfaces\Services\PlanPricingInterface::class)`, PHP classes inject it. Rationale: one formatting/promo rule set, testable, no global view composer magic.
2. **Promo is honest by construction.** `isPromoActive()` is true only when `promo.enabled` AND `promo.price > 0` AND `promo.price < regular price` AND `promo.ends_at` parses to a future datetime AND `promo.stripe_price_id` is filled. Checkout then uses the promo Stripe price id, so a displayed promo price is always the charged price, and the countdown always targets the real `ends_at`. Off by default. `original_price` is deleted.
3. **Gateway keeps its shape, gains two methods, loses one.** `cancelSubscription` (immediate cancel; contradicted the "access until period end" copy) is replaced by `cancelAtPeriodEnd()` and `resumeSubscription()`; `retrieveCheckoutSession()` returns a richer normalized array incl. ownership fields and the first invoice. The Stripe client is created lazily, because `new StripeClient('')` throws (`api_key cannot be the empty string`, vendor `BaseStripeClient.php:405`) and tests run with an empty key.
4. **Stripe API shape (stripe-php v20.1.0, API `2026-04-22.dahlia`).** Subscription periods live on `items.data[0].current_period_start/end`; invoice → subscription id lives on `parent.subscription_details.subscription`; `invoice.payment_intent` is gone. A pure helper `App\Services\StripePayloadMapper` (final class, static methods) reads new shape first, legacy top-level fields as fallback, always via `?? null` (StripeObject `__isset`, no notices). Used by both `StripeGateway` and `SubscriptionService` (DRY).
5. **Status enum is not altered.** `subscriptions.status` enum is `active, canceled, past_due, trialing, incomplete` (SQLite CHECK in tests). Mapper maps Stripe statuses: `active|trialing|past_due|canceled|incomplete` → same; `unpaid|paused` → `past_due`; `incomplete_expired` → `canceled`; unknown → `incomplete`.
6. **Pro-access rule (`Subscription::isActive`)**: plan must be professional (checked by `isProfessional`), `current_period_end` must be null-or-future, and status ∈ {active, trialing}, OR status = canceled with a non-null future `current_period_end`. `past_due`/`incomplete` → Free ("unpaid falls back to Free"). On `customer.subscription.deleted` the service sets `current_period_end = ended_at ?? now()` so a really-ended subscription loses access immediately. `User::plan_limits/hasFeature/canCreate` stay the source of truth for limits (unchanged values).
7. **Ownership of checkout sessions.** Checkout sets `client_reference_id = user id`, `metadata.user_id` and `subscription_data.metadata.user_id`. `handleCheckoutSuccess` accepts the session only if: the gateway finds it; `status === 'complete'`; `subscription_id` present; `client_reference_id ?? metadata_user_id` equals the auth id (`hash_equals`), and any present `metadata_user_id` also equals it; and if the user's local subscription already has a `stripe_customer_id`, the session `customer_id` matches it. Otherwise it throws `App\Exceptions\CheckoutSessionNotFoundException` → controller `abort(404)`, no DB write. Missing `session_id` → 404.
8. **Payment history = one row per Stripe invoice.** `PaymentHistoryRepository::upsertForInvoice($userId, $invoiceId, $data)` (`updateOrCreate(['user_id','stripe_invoice_id'])`). A failed attempt later paid becomes one `paid` row; checkout-success (expanded invoice) and `invoice.paid` webhook converge on the same row. Amount = `amount_paid / 100` from the invoice; only when Stripe gives no amount the default is `PlanPricing::currentPrice()`. Rows without an invoice are not created.
9. **Webhook idempotency** via additive table `stripe_webhook_events` (uuid PK, `stripe_event_id` unique, `type`, `processed_at`, timestamps, softDeletes). `SubscriptionService::handleWebhookEvent()` runs inside `DB::transaction`: `markProcessed()` (returns false if the id exists or the insert hits the unique constraint) → handler. A handler exception rolls back the marker so Stripe's retry is processed; controller returns 500 then. Missing secret or bad signature → 400.
10. **`checkout.session.completed` webhook** re-reads the session through `gateway->retrieveCheckoutSession($id)` (period data is not on the session object) and activates for the owner id resolved from `client_reference_id ?? metadata.user_id`, only if that user exists. Same `activateFromCheckout()` path as the success page, so both are idempotent (`updateOrCreateForUser` by user_id).
11. **Plan management** has no route parameters (acts on `Auth::user()`'s own subscription only), so cross-user access is impossible by construction; domain failures throw `App\Exceptions\SubscriptionActionException` (pt-BR message) → flash error. Cancel = cancel at period end; resume allowed only when `cancel_at_period_end` and period end is future. Confirmation via the existing `data-confirm` SweetAlert2 hook in `resources/js/forms.js`.
12. **CSP fix**: `SecurityHeaders` sends `form-action 'self'`; Chrome applies form-action to the 302 after `POST /assinatura/checkout`, which would block the redirect to `checkout.stripe.com`. Add `https://checkout.stripe.com` to form-action.
13. **"Financeiro"** = the existing `subscription.index` page (route name kept, so `PagesSmokeTest`, `GuestAccessTest`, `ReportAccessTest` keep working), retitled "Financeiro", with a new top-level desktop nav link and the mobile "Assinatura" link relabeled "Financeiro". Payment history paginated (10/page).
14. **Tests use `Tests\Fakes\FakeStripeGateway`** (implements the interface; records calls; returns configurable arrays; `constructWebhookEvent` delegates to `\Stripe\Webhook::constructEvent`, which is a local HMAC check). `phpunit.xml` forces empty Stripe keys so no test can ever reach Stripe with the real key.
