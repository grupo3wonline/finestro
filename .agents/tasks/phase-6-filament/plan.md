## Design decisions

1. **Separate `admin` session guard** (`config/auth.php`: `'admin' => ['driver' => 'session', 'provider' => 'users']`, panel `->authGuard('admin')`). Filament only challenges MFA on its own login page; with the shared `web` guard an admin logged in through the user app (no MFA) would enter `/admin` unchallenged. A separate guard forces every admin through `/admin/login` (email + password + TOTP). Guests of `/admin` are redirected to **the Filament login `/admin/login`** (documented). Logging out of either app invalidates the shared session (documented).
2. **Spatie guard pinned to `web`**: add `protected string $guard_name = 'web';` to `App\Models\User`. Filament calls `Auth::shouldUse('admin')`, which changes `auth.defaults.guard`; without the pin, `hasPermissionTo('admin.access')`/`assignRole('admin')` would look for `admin`-guard roles and throw `PermissionDoesNotExist`/`RoleDoesNotExist`. `Spatie\Permission\Guard::getNames()` reads the `guard_name` default property first (vendor code read).
3. **Access rule** `User::canAccessPanel(Panel $panel): bool` = `$panel->getId() === 'admin' && ! $this->isSuspended() && $this->hasVerifiedEmail() && $this->hasRole('admin') && $this->hasPermissionTo('admin.access')`. Filament's `Authenticate` middleware returns 403 when false; its login rejects such users.
4. **Authorization inside the panel** uses Filament `can*` methods, not model policies, through a trait `App\Filament\Concerns\RequiresAdminAccess` (`canAccess`, `canViewAny`, `canView` => `admin.access`; `canCreate/canEdit/canDelete/canDeleteAny/canForceDelete/canRestore...` => false). Registering `UserPolicy`/`SubscriptionPolicy` globally would change Gate behaviour for these models in the user app, which Phase 1 audited. Every custom action also calls `->authorize(...)` so a Livewire call by a non-admin is rejected server-side.
5. **Login throttling:** Filament's `Login` page already rate-limits (5 attempts/minute per IP via `danharrin/livewire-rate-limiting`) and the MFA challenge has its own limiter. Kept; tested.
6. **MFA:** `->multiFactorAuthentication([AppAuthentication::make()->recoverable()->brandName('Finestro')], isRequired: true)`. No `->profile()` page (it would let admins edit password/email from the panel; brief: no password editing). Recovery: 8 one-time recovery codes shown at setup; a lost device + lost codes is handled by an artisan command `finestro:admin-mfa-reset {email}` that clears both columns (logged), forcing setup on next login.
7. **First admin:** artisan command `finestro:make-admin {email}` promotes an EXISTING user who registered through the normal app flow (email must be verified). No password in code; `make:filament-user` must not be used (it skips `username`/roles).
8. **Suspension:** additive `users.suspended_at` (nullable timestamp, indexed). Enforcement: (a) `LoginRequest::authenticate()` uses `Auth::attemptWhen(..., fn (User $u) => ! $u->isSuspended())` and, when the credentials were valid but the user is suspended, shows `User::SUSPENDED_MESSAGE`; (b) new middleware `App\Http\Middleware\EnsureAccountIsActive` appended to the `web` group logs out an existing suspended session and redirects to login with the message; on the API v1 group (after `auth:sanctum`) it throws `AuthorizationException(User::SUSPENDED_MESSAGE)` (403 `forbidden` envelope); (c) suspend revokes all Sanctum tokens; (d) `canAccessPanel` blocks the panel. Message: `"Sua conta está suspensa. Entre em contato com o suporte para mais informações."`.
9. **Writes go through services.** New `App\Services\AdminUserService` (+ interface) owns promote/demote, suspend/unsuspend, resend verification and delete; it enforces "not on yourself" (demote, suspend, delete) and "at least one active admin remains" (active admin = role `admin`, not suspended, not soft-deleted) and throws `App\Exceptions\AdminActionException` with pt-BR messages; Filament actions catch it and show a danger notification. Delete calls `AccountDeletionServiceInterface::delete($user, $admin)` so Stripe cancellation rules and the pt-BR `AccountDeletionException` messages are reused.
10. **Causer is explicit.** `SecurityActivityLoggerInterface::log(string $event, ?User $subject, array $properties = [], ?User $causer = null)`; precedence `$causer ?? Auth::user() ?? $subject` (login_failed stays anonymous). `AccountDeletionServiceInterface::delete(User $user, ?User $actor = null)` forwards `$actor`. Existing callers unchanged (new params are optional).
11. **Reads go through repositories.** `AdminUserRepositoryInterface` (users query with eager `roles` + `subscription`, counts, active admins count), `AdminBillingRepositoryInterface` (subscriptions query, payments query, counts by status, MRR base count, month payments), `ActivityRepositoryInterface::adminQuery()`. Filament `getEloquentQuery()` returns those builders. Dashboard numbers come from `AdminMetricsService::metrics(): AdminMetricsData` (Laravel Data DTO).
12. **Professional counting in SQL** via `Subscription::scopeGrantingProfessional()` mirroring `Subscription::isProfessional()` (plan professional AND (period end null or future) AND (status active|trialing OR (status canceled AND period end not null))). A test compares the scope with the PHP method across factory states.
13. **MRR estimate** = number of subscriptions with plan `professional`, status `active`, period end null or future, × `PlanPricingInterface::regularPrice()`. Labelled "Estimativa" in the widget; promo/trial nuances documented. Never a hard-coded price.
14. **Data minimisation:** resources exist only for `User`, `Subscription`, `PaymentHistory`, `Spatie\Activitylog\Models\Activity`. Panel global search disabled. User view shows account/access/billing fields only. Activity entries whose `subject_type` is a financial model (`Wallet`, `Transaction`, `Goal`, `Budget`, `Category`, `AiCredential`, `TransactionHistory`, `WalletMember`, Media) show event + type + date only; `attribute_changes`/`properties` are hidden. Avatars use a local initials data-URI provider instead of ui-avatars.com (admin names are not sent to a third party).
15. **CSP scoped to /admin.** Expected change: none. Filament assets are self-hosted (`'self'`), Livewire update responses are JSON (CSP skipped), Alpine needs `'unsafe-eval'` which the CSP already allows, the font is loaded with `GoogleFontProvider` (fonts.googleapis.com/gstatic already allowed) instead of Filament's default Bunny Fonts, avatars are `data:` URIs, MFA QR codes are `data:` SVG. `SecurityHeaders::buildContentSecurityPolicy(Request $request)` gets a narrowly scoped hook `adminSources()` used only when `$request->is('admin', 'admin/*')`; it stays empty unless the implementer finds a violation (then add only that source and document it). A test asserts every external origin in the `/admin/login` HTML is allowed by the CSP header.
16. **Phase 5 / IP limiter:** new middleware `App\Http\Middleware\ThrottleApiByIp` that wraps (composition, NOT inheritance) `Illuminate\Routing\Middleware\ThrottleRequests` with the named limiter `api-ip`. Reason: Laravel's middleware priority list puts `AuthenticatesRequests` before `ThrottleRequests`, so a second `throttle:` entry would be sorted after `auth:sanctum` again; a class that is not a `ThrottleRequests` subclass keeps its declared position. Limit `config('api.ip_rate_limit_per_minute')` (env `API_IP_RATE_LIMIT_PER_MINUTE`, default 120), key `api-ip:{ip}`. Per-user `api` limiter unchanged except removing the dead `?? $request->ip()` fallback.
17. **Phase 5 / Scout subquery:** new `App\Support\Scout\SubqueryDatabaseEngine extends Laravel\Scout\Engines\DatabaseEngine` with `public function searchQuery(Laravel\Scout\Builder $builder): Illuminate\Database\Eloquent\Builder { return $this->buildSearchQuery($builder); }`, registered in `AppServiceProvider::boot()` with `resolve(EngineManager::class)->extend('database', fn () => new SubqueryDatabaseEngine)`. `TransactionRepository` replaces `searchKeys()` with `searchSubquery()` returning `Transaction::search($escaped)->query(fn ($q) => $q->select('transactions.id'))` built by the engine (`$builder->engine()`), used as `whereIn('transactions.id', $subquery->toBase())`. `buildSearchQuery()` adds no ORDER BY and `take(null)`, so the subquery is valid in MySQL `IN (...)`. Keeps `newScoutQuery()` (user scope + SoftDeletes) and the wildcard escaping. Fallback for a non-database Scout driver: keep the old `keys()` path (documented). No PHP id list for the database driver, so list + summary each run one SQL query and nothing is materialised twice.
18. **Phase 5 / wallet update:** `UpdateWalletRequest` adds `company_name`, `company_document`, `credit_limit`, `closing_day`, `due_day` with the exact store rules (nullable). Same request serves web and API. `wallets/edit.blade.php` gets the same business/credit-card fields as `create.blade.php` (targeted edit, values `old('x', $wallet->x)`), so the invoice redirect "Informe o dia de fechamento..." to `wallets.edit` finally works. Note: `WalletDTO::toArray()` drops nulls, so sending `null` leaves a field unchanged (documented in the OpenAPI description). New OpenAPI schema `WalletUpdateInput` (no `required`), PUT/PATCH descriptions say partial bodies are accepted.
